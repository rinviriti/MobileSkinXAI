# MacBook and physical iPhone testing

1. Use the recorded Flutter3.50.0/Dart3.14.0 SDK, compatible macOS/current Xcode and CocoaPods. Record `flutter --version`, `xcodebuild -version` and `flutter doctor -v`. Configure Xcode command-line tools/license/platform support on the Mac. None of these Mac actions was performed in WSL.
2. From app/flutter run `bash packages/mobileskinxai_codec/build_ios_codec.sh` after installing CMake. It builds the pinned scalar-C codec forarm64iphoneos andarm64iphonesimulator and creates an XCFramework. Existing frameworks are preserved; explicitly archive/version before rebuilding. This build MUST succeed before pod install. Recheck vendored license notices.
3. Run `flutter pub get`; enter ios/, run `pod install`, then return to app/flutter and open ios/Runner.xcworkspace. Verify native framework inclusion, retained msx_*symbols and resolved TensorFlowLite2.12.0 pods. Runner/Podfile target15.0. Set the team, unique bundle identifier, development signing and phone trust/Developer Mode.
4. Run `flutter analyze` and `flutter test`. The current SDK flags existing Material imports as informational deprecations; do not conceal new errors. Run `flutter test integration_test/model_device_test.dart -d <iphone-device-id>` for ACTUAL packaged codec/asset/interpreter golden parity. It checks the original four byte hashes, original maximum/mean logit/probability bounds and top-1 agreement. Save the integration reportData and device/build logs. WSLhost paths/overrides must NOT be used on the phone.
5. Build/run the normal app with `flutter run -d <iphone-device-id>`. Test original image selection, Preview, Analyze, real four-score results, corrupt/unsupported input, duplicate taps, navigation/disposal, permissions, EXIFrotation and unchanged design. Keep heatmaps absent. A test target bundles golden images only in test code; normal main.dart does not import that code.
6. Check ORIGINAL camera/gallery bytes and content type. iPhone photos may beHEIC. The adapter rejectsHEIC and has no converter. Do not introduce Photos/UIImage/third-party HEICtoJPEG conversion as an invisible fallback. Either explicitly select a genuine JPEG/PNG source for the verified path, or separately specify and validate an additional acquisition/conversion policy before enabling it. Audit the platform picker's returned representation and any metadata removal. This remains a real-device gate.
7. Measure actual phone preprocessing/inference time and memory only after correctness passes. No phone latency is predicted here. Verify release signing/symbol stripping and repeat golden parity in the release/AOTruntime before claiming mobile compatibility. Archive exact app/model/codec hashes and versions.

If a gate fails, preserve evidence and stop; do not change the trained model or tolerances. Never switch candidates based on historical PAD outcomes or show fake scores/XAI.

References: [Flutter iOS setup](https://docs.flutter.dev/platform-integration/ios/setup), [iOS deployment](https://docs.flutter.dev/deployment/ios), [pinned TFLite plugin](https://pub.dev/packages/tflite_flutter/versions/0.12.1), [image-picker permissions](https://pub.dev/packages/image_picker). No physical iPhone build/test was performed here.
